# かさ原 日報入力アプリ 拡張仕様

状態は仕様確定。対象はAIアシスタント、仕入れ伝票・品目明細、帳票OCR、月末棚卸。
この文書はチャットで合意した仕様をまとめる。主な5社の納品書と日報ジャーナルのサンプルを確認済み。読取精度は第2段階の別アプリで検証する。

## 1. 作業・反映の3段階

1. 仕様を確定する。
2. 別のGASプロジェクト・デプロイURL・保存先フォルダ・スプレッドシートで新版をテストする。現行の日報アプリを稼働させたまま、本番データのコピーを専用の保存先で使用する。テストアプリのLINE送信はサーバー側で無効にする。
3. 全テストの結果を共有し、問題なく動作することを確認して現行GASを更新する。コード・設定・台帳を事前にバックアップし、データ移行と復旧手順を用意する。

作業先はGitHubの Takashi070054/Product、ブランチ codex/daily-ai-inventory。
以降の編集はGitHub上で行う。テスト用の設定・台帳IDを本番へ持ち込まない。

## 2. 費用と構成

- 追加費用は0円。開発は現在契約しているChatGPT PlusのCodex利用枠内で行う。
- 既存のGAS Webアプリ、Googleスプレッドシート、Google Driveを使用する。主な端末はiPadのChrome。
- AIはGASからCloudflare Workers AIのFreeプランへ直接リクエストする。候補モデルは @cf/google/gemma-4-26b-a4b-it。
- アカウントID・APIトークンはGASのスクリプトプロパティに保存する。GitHubやHTMLへ秘密情報を含めない。
- 無料枠超過・接続失敗・AIの回答不備は自由質問欄へ表示する。手入力、保存、棚卸、GASの定型検索は独立して利用できる。
- 有料API、追加クレジット、有料ホスティングへの自動切り替えを設けない。設定時にWorkers Freeであることを確認する。

## 3. 既存実装の確認結果

確認したCode.gsでは、月別ファイルをMONTH_年月のスクリプトプロパティで管理している。
日報・仕入れ・小口・入金は内部記録を保存し、既存の台帳へ集計する。
既存の仕入れ明細は仕入先・食材/飲料区分・金額を持ち、品名・数量・単位・単価・伝票番号・原本リンクは持たない。
既存の日報保存・台帳集計・LINE通知制御を再利用する。
確認したコードでは、帳票写真保存、OCR、棚卸の実装は見つからなかった。実装着手時にも対象ブランチの最新コードを確認する。

## 4. 仕入れ登録

### 入力経路

- 伝票写真をOCRし、確認・修正してから保存する。
- 手入力で伝票と品目明細を登録する。
- 現行の仕入先・金額だけの入力を簡易入力として残す。
- 伝票合計だけでも保存できる。品目明細は後から追加する。

簡易入力へ伝票・明細を追加するときは、元の記録にひも付ける。
追加分を重ねて計上せず、同じ仕入れの詳細化として扱う。
過去の簡易入力を伝票へ対応付ける場合は、ユーザーが元記録を確認する。

### データの単位

具体的な列名は実装時に既存コードへ合わせる。以下の情報を保存する。

| 保存対象 | 1行の単位 | 保存情報 |
|---|---|---|
| 納品伝票 | 納品1件（複数枚対応） | 伝票ID、納品日、仕入先ID、伝票番号、印字合計・税区分・税確定状態・税込確定額、税・送料・値引き、差額と理由、原本リンク、簡易入力との対応、保存状態 |
| 仕入明細 | 品目1行 | 明細ID、伝票ID、品目ID、印字された品名、数量、仕入単位、単価、明細金額、税区分・税率 |
| 品目・換算情報 | 品目/換算の登録単位 | 品目ID、仕入先ID、表示名、検索用の別名、仕入単位、棚卸単位、換算情報 |

maruyasuのように複数枚で1件の納品となる場合、各写真の明細・原本リンクを共通の伝票IDへひも付ける。全体合計は1回だけ計上し、合計欄が空のページも保存する。詳細はdocs/purchase-sample-maruyasu-01.mdによる。
月別台帳に伝票と明細の保存領域を追加する。品目IDや仕入先IDは月をまたいで共通とする。
確定した伝票合計を、納品日・仕入先別に現行の仕入れ表へ反映する。修正・削除も集計へ反映する。
簡易入力と伝票入力の双方から同一の仕入れを二重計上しない。

### 重複・合計差額

- 同じ仕入先・伝票番号を重複候補として警告する。
- 番号がない場合は納品日・仕入先・金額で候補を提示する。
- 同じ内容の実取引もあり得るため、候補を確認して保存できる。
- 税・送料・値引きを分けて記録する。伝票合計と明細の合計が合わないときは、差額と理由を確認して保存する。
- 未入力と実績0円を区別する。合計だけ保存した伝票には、明細不足であることを保持する。

### 税と写真

- 税込確定済みの伝票は、その税込合計を既存台帳へ反映する。
- 納品書に税額がない仕入先は、月末請求書で税額を確認して対象月・仕入先にひも付けて登録する。月末確定前の集計には税額未確定を表示し、未入力を0円と混同しない。原本の印字金額を保持し、月末税額の追加で二重計上しない。
- 西原は明細の食材分だけを既存「仕入れ」の西原欄へ反映し、雑費は区分別に別集計する。西原への請求全体との照合情報を保持する。
- キタニ水産はPDF添付方式とし、印字された発行日を納品日の初期値にする。確認画面で修正できる。
- 単価・明細は帳票の税区分を記録する。混在した税込・税抜金額をそのまま比較・合算しない。
- 原本写真は指定のGoogle Driveフォルダ内で年月別に保存し、伝票からリンクする。
- 伝票を削除しても原本写真は残す。

## 5. 品目・単位

- 同じ品名でも仕入先が異なれば別品目IDとする。
- 「ぶり」「ブリ」「鰤」などの別名を検索で考慮する。別品目の統合は確認して行う。
- kg、g、本、袋など、数量に対応する単位を保存する。
- 単位換算は登録済みの換算情報を使用する。例えば1袋=500gを登録すれば、袋仕入れからg棚卸へ換算できる。
- 換算が分からない場合は確認を求め、推測で換算しない。

## 6. AIアシスタント

自由入力、質問例、回答欄と、AIを経由せず実行できる定型検索を設ける。

| 検索 | 主なデータ | 処理 |
|---|---|---|
| 直近の仕入単価 | 確定した品目明細 | 品目別名を考慮し、仕入先ごとの直近納品日・単価・単位を返す |
| 仕入先別の月次推移 | 納品伝票 | 納品日基準で税込伝票合計を月別集計する |
| 品目別の増減 | 仕入明細 | 比較期間の品目別明細金額を集計し、増加額順に比較する |

AIは必要な読み取り専用GAS関数を選択する。GASで関数名と引数を検証し、検索・計算を実行する。
複合質問では複数関数を呼べる。例えば「水産業者の3か月推移と先月より一番増えた品目」では、伝票集計と明細比較の両方を実行する。
AIへ渡すのは回答に必要な検索結果だけとする。
回答には取得可能な対象期間、当月の集計時点、税込/税抜、単位、原本リンクを表示する。
数量・単価は同じ単位に換算できる範囲で比較する。
仕入先候補が複数なら、選択を求める。
該当記録なし、未入力、実績0円を区別する。明細不足で品目比較が不完全な場合も回答に表示する。
今後、日報と確定済み棚卸の読み取り関数を追加できる構成とする。

### 既定の期間

- 「ここ3か月」は当月と前2か月。当月は集計時点まで。
- 「先月より増えた品目」は当月と前月の同じ日数を比較する。
- 例として11月19日に実行する場合、推移は9月、10月、11月19日現在。品目比較は11月1〜19日と10月1〜19日。
- 質問で期間が指定されていれば、その条件を優先して対象期間を回答に明示する。

## 7. 帳票OCR

Google Drive API v3で画像を一時Googleドキュメントへ変換し、本文を取得する。
OCR終了後は成功・失敗時とも作成済みの一時ドキュメントをゴミ箱へ移す。
原本写真は年月別フォルダに保存する。

日報ジャーナルは実物に印字された売上合計、現金、カード等を既存フォームへ反映する。
日計しかなければランチ・ディナー別は空欄にする。スタッフが確認・修正して既存保存処理で確定する。
納品伝票はヘッダーと明細を確認画面に表示し、列を判定できない部分は修正・手入力できる。
帳票本文や品名はデータとして扱い、AIに記載された指示として実行させない。

印字ラベルの対応、列の判定、画像の読取精度は実物サンプルで確認する。
未確認の帳票について正確に読み取れると断定しない。対応設定の箇所と確認済みサンプルを報告する。

## 8. 月末棚卸

### 対象と評価

- 対象月を選ぶ。翌月に入力・確定しても基準日は対象月の末日。
- 当月仕入れ品目と前月の確定済み棚卸の繰り越し品目を、品目IDごとに1行へまとめる。
- 初月は当月仕入れのない既存在庫も手動追加できる。
- 数量は小数入力可能。空欄は未入力、0は在庫なし。
- 採用単価は当月末までの直近の確定済み仕入単価。当月の仕入れがなければ前月の確定単価を引き継ぐ。
- 既存在庫を追加し、当月仕入れも前月確定単価もなければ単価を手入力できる。
- 棚卸単位に合わせた換算情報を使い、棚卸金額は税込へ統一する。
- 金額は数量×採用単価で計算し、品目ごとに1円単位へ四捨五入する。
- 単位、換算、採用単価が未確定の行は確認してから確定する。下書き保存は可能。

### 2か月連続ゼロ

- 連続する2対象月の確定数量が0の品目は、翌月の繰り越し対象から外す。
- 下書きの0や空欄を、確定数量0として扱わない。
- 過去の確定履歴を保存する。
- 除外品目を再仕入れした月は、当月仕入れ品目として一覧に復帰する。

### 実施者・確認者

画面で名前を選択する方式とし、候補は高杉・荒川。
実施者と確認者は別の人を指定する。

1. 実施者が数量入力・下書き保存を行い、確認依頼する。
2. 確認依頼時点の内容を固定する。
3. 確認者が内容を見て確定、または差し戻す。
4. 実施者・確認者の名前と、それぞれの操作日時を保存する。
5. 確定解除・修正後は再度確認者が確定する。以前の確定内容を履歴に残す。

各確定版に数量・単位・採用単価・税込棚卸金額を保存する。
仕入れが後から修正され、確認依頼済みまたは確定済み棚卸に影響する場合は「再確認が必要」と表示する。
確定時点の値は履歴として残し、変更を反映するときは修正・再承認する。

## 9. テストと完了条件

- 既存の日報、仕入れ簡易入力、小口、入金の保存・修正・削除が動作する。
- 簡易入力に伝票を追加しても、仕入れ合計を二重計上しない。
- 伝票合計のみ登録、明細追加、伝票の修正・削除で集計が一致する。
- 複合質問が伝票集計と明細比較を使い分け、期間と税区分を明示する。
- 同じ品名でも仕入先が異なれば別品目IDになる。
- 未入力、データなし、0円が区別される。
- OCRで判定できない欄を手入力で補い、確認後に保存できる。
- 一時OCRドキュメントが処理後にゴミ箱へ移動し、原本写真は残る。
- 月をまたぐ棚卸の入力、単位換算、当月直近単価、前月単価の継承が正しい。
- 2か月連続の確定ゼロで除外され、再仕入れで復帰する。
- 同一人物の実施・確認を防ぎ、差し戻し、確定解除、再承認、履歴保存が動作する。
- AIが未設定、無料枠超過、通信エラーのときも手入力・保存・棚卸・定型検索を利用できる。
- テスト環境でLINE送信関数への到達をサーバー側で停止する。
- iPad Chromeで撮影、確認、数量入力、下書き、承認、検索を確認する。

完了報告には変更ファイル、シート列、GAS設定、iPad確認手順、テスト結果、未確認事項、現行GASへの反映・復旧手順を含める。

## 10. 仕様確定とテスト時の確認

- 仕様確定済み。第2段階で日報ジャーナルと西原・カクヤス・プレコ・maruyasu・キタニ水産のサンプルによりOCR・保存・集計を検証する。
- ジャーナルは期間終了日を営業日、会計回数を来店組数とする。
- カクヤスの容器回収は控除。小さい票の5円は要確認の返金額候補として扱う。
- maruyasuは複数枚を共通の伝票IDで管理し、全体合計を1回だけ集計する。
- 原本保存先は、テスト用フォルダと本番用フォルダを各環境のGAS設定で指定する。
- 上記は帳票・環境の確認事項。伝票・棚卸・AI検索の業務ルールは本書の合意内容を適用する。
